# Vision Lego — Claude Code Project Guide

## Project configuration

- **Framework**: SvelteKit (fullstack monolith)
- **Language**: TypeScript
- **Package manager**: pnpm
- **ORM**: Drizzle + PostgreSQL (existing instance, no Docker)
- **Auth**: Better Auth (email + password)
- **Payments**: Wompi — REST API integration (integrate last, replaces original MercadoPago plan)
- **Styles**: Tailwind CSS with `typography` and `forms` plugins
- **Image cropping**: cropperjs v1.6.x (square crop + zoom/pan modal before upload)
- **Testing**: Vitest (unit + component) + Playwright (e2e)
- **Currency**: COP (Colombian pesos), no decimals
- **Local project name**: `vision_lego`
- **Brand name**: Vision Lego (shown to end users)

## MCP tools available

### Svelte MCP (`https://mcp.svelte.dev/mcp`)
Use this throughout the entire project:
- Call `list-sections` at the start of every task to identify relevant documentation
- Call `get-documentation` to fetch up-to-date docs before writing any Svelte/SvelteKit code
- Run `svelte-autofixer` on **every** `.svelte` component before delivering it — keep iterating until there are zero errors and zero suggestions

### Wompi (payment integration — no MCP available)
Wompi replaces MercadoPago by client decision — lower transaction fees for Colombia.
- No MCP server available for Wompi — use the official REST API docs at https://docs.wompi.co
- Integration approach: Wompi REST API (server-side order creation + signature) or Wompi JS widget (client-side)
- Do not start this integration until the owner provides their Wompi merchant credentials (public key + private key)
- DB fields `mpPaymentId` and `mpStatus` on the `orders` table must be renamed to `wompiPaymentId` and `wompiStatus` when starting this step — generate a Drizzle migration for this change

## Database — Drizzle schema

**The schema file lives at `src/lib/server/db/schema.ts`.** This is the default location generated by `sv add drizzle` and what `drizzle.config.ts` points to. Claude Code can read, edit, and run migrations from there.

### Enums
```ts
orderStatus: 'pending' | 'paid' | 'processing' | 'shipped' | 'delivered' | 'cancelled' | 'refunded'
productCategory: 'sunglasses' | 'optical'
```

### Tables

**Auth — required by Better Auth, do not change structure**
- `users` — id, name, email, emailVerified, image, role ('customer'|'owner'|'staff'), createdAt, updatedAt
- `sessions` — id, userId, token, expiresAt, ipAddress, userAgent, createdAt, updatedAt
- `accounts` — id, userId, accountId, providerId, accessToken, refreshToken, password, ...
- `verifications` — id, identifier, value, expiresAt, createdAt, updatedAt

**Catalog**
- `brands` — id, name, slug, logoUrl, createdAt
- `products` — id, name, slug, description, category, brandId, gender, basePrice, isActive, isFeatured, createdAt, updatedAt
- `productVariants` — id, productId, color, size, material, sku, price (override), stock, isActive
- `productImages` — id, productId, variantId (nullable), url, altText, position, isPrimary

**Store**
- `cartItems` — id, userId, variantId, quantity, addedAt
- `wishlistItems` — (userId, productId) composite PK, addedAt

**Orders**
- `orders` — id, userId, customerName, customerEmail, customerPhone, shippingAddress, shippingCity, shippingDept, shippingZip, shippingMethodId, shippingCost, status, total, mpPaymentId (nullable), mpStatus (nullable), notes, createdAt, updatedAt

**Business**
- `expenses` — id, description, amount, category, date, notes, createdAt
- `receivables` — id, customerName, customerPhone, description, amount, paidAmount, dueDate, isPaid, createdAt, updatedAt
- `shippingMethods` — id, name, description, cost, isActive, createdAt

## Code conventions

### General
- Use Svelte 5 with runes (`$state`, `$derived`, `$effect`, `$props`) — never Svelte 4 legacy syntax
- All server logic goes in `+page.server.ts` and `+server.ts` — never expose DB to the client
- Validate forms with SvelteKit Form Actions
- Private environment variables from `$env/static/private`

### Currency formatting
```ts
// src/lib/utils/currency.ts
// Always use this function to display prices
export function formatCOP(amount: number): string {
  return new Intl.NumberFormat('es-CO', {
    style: 'currency',
    currency: 'COP',
    minimumFractionDigits: 0,
  }).format(amount)
}
```

### IDs
- Use `crypto.randomUUID()` for all entity IDs

### Product images
See `docs/IMAGE_STANDARDS.md` for the full image processing spec, sizes, formats, and the ProductImage component API.
The owner-facing photo guide lives at `guia-fotos-productos.txt` (Spanish, plain language).

### Route protection for `/negocio`
```ts
// src/hooks.server.ts
// Check session and role on every request to /negocio
// Redirect to /iniciar-sesion if no session
// Redirect to / if session exists but role === 'customer'
```

### Responsive design and mobile-first
Vision Lego targets both mobile and desktop buyers. Mobile is a primary audience.
- Write all CSS mobile-first using Tailwind's responsive prefixes (`sm:`, `md:`, `lg:`) — scales naturally to desktop without breaking anything
- Tap targets minimum 44px height on all interactive elements
- Product image gallery on `/productos/[slug]` must be swipeable on mobile
- Navigation on mobile: hamburger or bottom nav — never a cramped horizontal bar
- `/negocio` dashboard: sidebar on desktop, bottom nav on mobile

### Visual style — public store (Vision Lego)
Competitive references studied: GMO (gmo.com.co), Gafas&Gafas (gafasygafas.com.co), Óptica Al Mayor.
Vision Lego must beat them on simplicity, speed, and trust — not on how much content is packed on screen.

**Do:**
- Let product photography be the visual hero — large, clean images, minimal UI clutter around them
- Use meaningful product names (e.g. "Marco Aviador Negro Mate") — never raw SKU codes
- Show price, brand, and a clear CTA on every product card
- Trust signals: free shipping notice, easy returns, secure payment logos — visible without scrolling
- Fast perceived load: SvelteKit SSR renders server-side by default, lazy-load images below the fold
- Homepage: featured products, category blocks, top brands — concise, not exhaustive

**Never:**
- No popup banners or email capture interrupts
- No external ads or third-party ad scripts
- No auto-playing carousels the user cannot control
- No SVG placeholder skeletons that make the page feel broken
- No decorative animations that delay interaction

### Visual style — /negocio dashboard
- Clean, functional UI — the owner is non-technical, every action must be self-explanatory
- All labels and copy in Spanish, no technical jargon
- Tailwind for all CSS — no inline styles except in exceptional cases

### How deployment works
Claude Code runs on `mikeydoya`'s local machine, not on the server. The build always happens locally. The droplet only receives the compiled output and runs it.

Deployment flow:
1. `pnpm build` runs locally on `mikeydoya`'s machine
2. Developer pushes to `main` on GitHub
3. GitHub Actions SSHes into the droplet as `mikey`
4. Actions transfers the compiled output (`build/`, `package.json`, `pnpm-lock.yaml`) to the droplet
5. Actions runs `pnpm install --prod` on the droplet (no build — production deps only)
6. Actions runs `pm2 restart vision_lego` (or `pm2 start ecosystem.config.cjs` on first deploy)
7. Nginx reverse-proxies HTTP traffic from port 80 to `localhost:3000`

### What Claude Code generates (automated)
- `.github/workflows/deploy.yml` — full GitHub Actions workflow (SSH as `mikey`)
- `ecosystem.config.cjs` — PM2 process config
- `nginx.conf` — HTTP-only Nginx reverse proxy (developer copies this to the server manually)

### What the developer does manually (one-time server setup)
The droplet has two users: `root` and `mikey`. Always use `mikey`.
`mikey` has passwordless sudo scoped only to Nginx and PM2 commands needed for deployment.

```sh
# 1. ✓ DONE — PM2 installed globally: pnpm add -g pm2

# 2. After the first successful deploy, register PM2 with systemd so it survives reboots
pm2 startup        # copy and run the command it prints
pm2 save

# 3. Allow Nginx (www-data) to traverse mikey's home directory so it can
#    serve files from /home/mikey/vision_lego/static/uploads/
#    Without this, GET /uploads/* returns 403 because Ubuntu 24 creates
#    home directories with mode 0750 (no access for "others").
sudo chmod o+x /home/mikey

# 4. Copy nginx.conf (generated by Claude Code) to the server
sudo cp nginx.conf /etc/nginx/sites-available/vision_lego
sudo ln -s /etc/nginx/sites-available/vision_lego /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### Feature — inline variant editing in `/negocio/productos/[id]` and `/negocio/inventario` (2026-04-22)
Variants can now be edited directly in the table rows without navigating to a separate page.

**Technique**: HTML5 `form` attribute — the `<form>` element lives in the last `<td>`, inputs in other `<td>` cells reference it via `form="edit-{id}"`. This avoids invalid `<form>` nesting inside `<tr>` while letting `use:enhance` collect all row inputs into one FormData submission.

**`/negocio/productos/[id]`**:
- "Editar" button (same gray style as OK) toggles the row to edit mode
- Edit row: Color, Talla, Material, SKU, Precio override, Stock inputs stacked/side-by-side
- "Guardar" submits `?/updateVariant` action; "Cancelar" reverts without saving
- `use:enhance` callback sets `editingVariantId = null` and `reset: false` after save
- Form ID: `edit-{variant.id}`

### Fix — form reactivity audit: use:enhance + invalidateAll across all routes (2026-05-03)
Root bug: forms with bare `use:enhance` submitted via AJAX but never called `invalidateAll()`, so the UI stayed stale until a manual page refresh (e.g. deleting a product left the row visible).

Fixed 22 forms across 11 files — every state-mutating form that stays on the same page now uses the full callback pattern:
```svelte
use:enhance={() => async ({ result, update }) => {
  if (result.type === 'success') { await invalidateAll(); } else { await update(); }
}}
```
Existing state cleanup (e.g. `saving = false`, `editingVariantId = null`, `showForm = false`, optimistic wishlist flip) was preserved and combined with `invalidateAll()`. The `?/salir` action in `/cuenta` was correctly left alone — it calls `redirect(302, '/')` which re-runs load automatically. `svelte-autofixer` returned zero issues on all 11 modified files; `pnpm build` passed.

### Fix — Nginx 403 on uploaded product images (2026-05-13)
Production images returned 403 Forbidden even though files were on disk at the expected path and the DB rows were correct. Root cause: Ubuntu 24 creates /home/mikey with mode 0750, so www-data (Nginx) couldn't traverse the home directory to reach static/uploads/. Fixed with `sudo chmod o+x /home/mikey` on the droplet. No code change, no redeploy. Documented the chmod step in the manual server setup checklist so future fresh-droplet setups don't hit this wall.

### Feature — client-side square crop modal before upload (2026-05-13)
Added a per-image cropper modal that opens automatically after the owner picks files in `/negocio/productos/[id]`. Each file goes through the modal in sequence before the upload form is submitted.

**New dependency**: `cropperjs ^1.6.x` (MIT) — installed as `cropperjs@1.6.2`. v2 was avoided (different API, no CSS file).

**`src/lib/components/ui/ImageCropper.svelte`** (new):
- Wraps cropperjs using `{@attach initCropper}` (Svelte 5 attachment API) — the canonical pattern for third-party DOM libraries
- Enforces: 1:1 aspect ratio, zoom cap at 100% of original (zoom event listener with `e.preventDefault()` when `detail.ratio > 1`)
- Output: `getCroppedCanvas({width:1600, height:1600})` → `canvas.toBlob(cb, 'image/webp', 0.92)`
- CSS imported via `<style>@import 'cropperjs/dist/cropper.css'</style>` — NOT a script import; Vite 8 / rolldown SSR build cannot resolve CSS imports from `<script>` blocks, but `<style>` imports go through Vite's CSS pipeline and work correctly
- Modal: fixed overlay, sheet-from-bottom on mobile (`items-end sm:items-center`), 55 vh cropper area, zoom +/− and Restablecer buttons, Cancelar / Continuar

**`src/routes/negocio/productos/[id]/+page.svelte`** (updated):
- `handleImageSelect` is now async — uses `createImageBitmap` for client-side dimension validation before opening the cropper; images below 1200×1200 px are rejected with a Spanish error banner, `bitmap.close()` frees memory
- State: `cropQueue: File[]`, `croppedBlobs: Blob[]`, `croppedPreviews: string[]`, `cropIndex: number`, `validationErrors: string[]`
- `{#key cropIndex}` forces ImageCropper to remount (destroy + recreate) for each file in the queue
- `use:enhance` appends blobs as `new File([blob], 'cropped-N.webp', {type:'image/webp'})` to FormData; `cancel()` guards against submission with no blobs
- `clearCropState()` revokes all preview object URLs to prevent memory leaks
- Server action (`uploadImages`) is unchanged — it still calls `processProductImage()` and reads `getAll('images')` from FormData
