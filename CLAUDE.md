# Vision Lego — Claude Code Project Guide

## Project configuration

- **Framework**: SvelteKit (fullstack monolith)
- **Language**: TypeScript
- **Package manager**: pnpm
- **ORM**: Drizzle + PostgreSQL (existing instance, no Docker)
- **Auth**: Better Auth (email + password)
- **Payments**: MercadoPago Checkout Bricks — Payment Brick (integrate last)
- **Styles**: Tailwind CSS with `typography` and `forms` plugins
- **Testing**: Vitest (unit + component) + Playwright (e2e)
- **Currency**: COP (Colombian pesos), no decimals
- **Local project name**: `vision_lego`
- **Brand name**: Vision Lego (shown to end users)

## Database — Drizzle schema

**The schema file lives at `src/lib/server/db/schema.ts`.** This is the default location generated by `sv add drizzle` and what `drizzle.config.ts` points to. Claude Code can read, edit, and run migrations from there.

### Enums
```ts
orderStatus: 'pending' | 'paid' | 'processing' | 'shipped' | 'delivered' | 'cancelled' | 'refunded'
productCategory: 'sunglasses' | 'optical'
```

### Tables

**Auth — required by Better Auth, do not change structure**
- `users` — id, name, email, emailVerified, image, role ('customer'|'owner'|'staff'), createdAt, updatedAt
- `sessions` — id, userId, token, expiresAt, ipAddress, userAgent, createdAt, updatedAt
- `accounts` — id, userId, accountId, providerId, accessToken, refreshToken, password, ...
- `verifications` — id, identifier, value, expiresAt, createdAt, updatedAt

**Catalog**
- `brands` — id, name, slug, logoUrl, createdAt
- `products` — id, name, slug, description, category, brandId, gender, basePrice, isActive, isFeatured, createdAt, updatedAt
- `productVariants` — id, productId, color, size, material, sku, price (override), stock, isActive
- `productImages` — id, productId, variantId (nullable), url, altText, position, isPrimary

**Store**
- `cartItems` — id, userId, variantId, quantity, addedAt
- `wishlistItems` — (userId, productId) composite PK, addedAt

**Orders**
- `orders` — id, userId, customerName, customerEmail, customerPhone, shippingAddress, shippingCity, shippingDept, shippingZip, shippingMethodId, shippingCost, status, total, mpPaymentId (nullable), mpStatus (nullable), notes, createdAt, updatedAt
- `orderItems` — id, orderId, variantId, productName (snapshot), variantLabel (snapshot), unitPrice, quantity, subtotal

**Business**
- `expenses` — id, description, amount, category, date, notes, createdAt
- `receivables` — id, customerName, customerPhone, description, amount, paidAmount, dueDate, isPaid, createdAt, updatedAt
- `shippingMethods` — id, name, description, cost, isActive, createdAt

## Audiences and authentication

### Customers (public store)
- Register with email + password via Better Auth
- Protected routes: `/carrito`, `/checkout`, `/cuenta`
- No access to `/negocio`

### Owner / Staff (dashboard)
- Login at `/iniciar-sesion` — same page as customers
- Redirect to `/negocio` if `role === 'owner' || role === 'staff'`
- **Protect all `/negocio/**` routes in `src/hooks.server.ts`**
- Owner account is created manually in the DB — no public admin registration
- Schema is roles-ready for future staff accounts, but only owner exists for now

## Public store — Features

### Catalog (`/productos`)
- Product grid with filters: category (gafas de sol / monturas ópticas), brand, gender, color, material, price range
- Filters work via URL search params (SSR-compatible)
- Sort by: price asc/desc, newest, featured
- Only show products where `isActive = true` and at least one variant has `stock > 0`

### Product detail (`/productos/[slug]`)
- Variant selector (color + size + material)
- Image gallery — updates based on selected variant
- Price updates per variant
- Stock indicator: disponible / últimas unidades / agotado
- "Agregar al carrito" button (requires login)
- "Agregar a lista de deseos" button (requires login)

### Cart (`/carrito`)
- Item list with editable quantity
- Subtotal per item and grand total in COP
- Button to proceed to checkout

### Checkout (`/checkout`)
- Form: nombre, email, teléfono, dirección, ciudad, departamento
- Shipping method selector (loaded from `shippingMethods` table)
- Order summary with total + shipping cost
- On confirm: create `order` with status `pending`, clear cart
- MercadoPago Checkout Bricks is wired in here at the end of the project

### Account (`/cuenta`)
- Order history with visual status
- Editable profile details
- Wishlist

## `/negocio` dashboard — Features

> Designed for a non-technical owner. Clear UI, simple actions, works well on mobile and desktop.

### Home (`/negocio`)
- Daily summary: today's sales, pending orders, low-stock products
- Quick-access shortcuts to the most-used sections

### Product management (`/negocio/productos`)
- Table/list of all products with search and category filter
- Create product: nombre, categoría, marca, género, descripción, precio base
- Per product: add variants (color + talla + material + price override + stock)
- Upload images: multiple file input, instant preview, reorderable, mark primary image
- Activate/deactivate product with a toggle
- Mark/unmark as featured

### Inventory (`/negocio/inventario`)
- View all variants with current stock
- Inline quick-edit of stock (numeric field)
- **Low-stock alerts**: highlight in red any variant with stock ≤ threshold (configurable, default 3)
- Filter to show only low-stock items

### Orders (`/negocio/pedidos`)
- Order list sorted by date descending
- Filter by status (pendiente, pagado, en proceso, enviado, entregado, cancelado)
- Order detail: customer info, items purchased, shipping address, shipping method
- Change order status with a visual selector (stepper or dropdown)
- Show MercadoPago payment data if available

### Expenses (`/negocio/gastos`)
- Record expense: descripción, monto COP, categoría (arriendo, nómina, proveedor, servicios, otro), fecha, notas
- Expense list with filter by month and category
- Monthly expense total always visible

### Receivables (`/negocio/cuentas-por-cobrar`)
- Record a debt: nombre del cliente, teléfono, descripción, monto total, monto pagado, fecha límite
- Mark as partially or fully paid
- List with visual status (pendiente / parcial / pagada)
- Highlight overdue debts

### Analytics (`/negocio/analiticas`)
- Sales report: income by day/week/month (date range selector)
- Line or bar chart with income over time
- Top 5 best-selling products
- Summary: total income, total expenses, net profit for the period
- All values in COP formatted (e.g. $1.250.000)

### Shipping methods (`/negocio/envios`)
- Create method: nombre (e.g. "Domicilio Medellín"), descripción, costo en COP
- Activate/deactivate methods
- Edit cost

## Code conventions

### General
- Use Svelte 5 with runes (`$state`, `$derived`, `$effect`, `$props`) — never Svelte 4 legacy syntax
- All server logic goes in `+page.server.ts` and `+server.ts` — never expose DB to the client
- Validate forms with SvelteKit Form Actions
- Private environment variables from `$env/static/private`

### Currency formatting
```ts
// src/lib/utils/currency.ts
// Always use this function to display prices
export function formatCOP(amount: number): string {
  return new Intl.NumberFormat('es-CO', {
    style: 'currency',
    currency: 'COP',
    minimumFractionDigits: 0,
  }).format(amount)
}
```

### IDs
- Use `crypto.randomUUID()` for all entity IDs

### Product images
- Store at `static/uploads/products/[productId]/`
- File name: `[uuid].[ext]`
- Accepted formats: jpg, jpeg, png, webp — max 5MB per image

### Route protection for `/negocio`
```ts
// src/hooks.server.ts
// Check session and role on every request to /negocio
// Redirect to /iniciar-sesion if no session
// Redirect to / if session exists but role === 'customer'
```

### Responsive design and mobile-first
Vision Lego targets both mobile and desktop buyers. Mobile is a primary audience.
- Write all CSS mobile-first using Tailwind's responsive prefixes (`sm:`, `md:`, `lg:`) — scales naturally to desktop without breaking anything
- Tap targets minimum 44px height on all interactive elements
- Product image gallery on `/productos/[slug]` must be swipeable on mobile
- Navigation on mobile: hamburger or bottom nav — never a cramped horizontal bar
- `/negocio` dashboard: sidebar on desktop, bottom nav on mobile

### Visual style — public store (Vision Lego)
Competitive references studied: GMO (gmo.com.co), Gafas&Gafas (gafasygafas.com.co), Óptica Al Mayor.
Vision Lego must beat them on simplicity, speed, and trust — not on how much content is packed on screen.

**Do:**
- Let product photography be the visual hero — large, clean images, minimal UI clutter around them
- Use meaningful product names (e.g. "Marco Aviador Negro Mate") — never raw SKU codes
- Show price, brand, and a clear CTA on every product card
- Trust signals: free shipping notice, easy returns, secure payment logos — visible without scrolling
- Fast perceived load: SvelteKit SSR renders server-side by default, lazy-load images below the fold
- Homepage: featured products, category blocks, top brands — concise, not exhaustive

**Never:**
- No popup banners or email capture interrupts
- No external ads or third-party ad scripts
- No auto-playing carousels the user cannot control
- No SVG placeholder skeletons that make the page feel broken
- No decorative animations that delay interaction

### Visual style — /negocio dashboard
- Clean, functional UI — the owner is non-technical, every action must be self-explanatory
- All labels and copy in Spanish, no technical jargon
- Tailwind for all CSS — no inline styles except in exceptional cases

## Deployment & infrastructure

### Target server
- **Provider**: DigitalOcean Droplet — Basic Intel, 1 vCPU, 1 GB RAM, 35 GB Disk (~$8/month)
- **OS**: Ubuntu 24 LTS
- **Already installed on server**: Nginx (latest) and Node.js (latest)
- **Adapter**: `adapter-node` — the SvelteKit build output is a plain Node.js server, entry point at `build/index.js`
- **Process manager**: PM2 — keeps the Node.js process alive, restarts on crash, survives reboots
- **Expected traffic**: low (under 10k visits), the droplet is well within capacity

### Node.js runtime
- **Local**: v24.15.0 — **Droplet**: v24.14.1 (Node.js v24 — now LTS as of October 2025)
- The app runs as a Node.js process via `node build/index.js` (managed by PM2)
- Default port: `3000` — Nginx proxies public traffic to this port
- Required env vars for `adapter-node` at runtime on the droplet:
  ```
  PORT=3000
  BODY_SIZE_LIMIT=5242880
  ```

### PostgreSQL setup (manual, one-time on the droplet)
PostgreSQL is installed (latest) but the database and user have not been created yet.
The developer must run these commands on the droplet before the first deploy:

```sh
sudo -u postgres psql

# Inside psql:
-- mikey user already exists, just set a password if not done yet:
ALTER USER mikey WITH PASSWORD 'your_strong_password';
CREATE DATABASE vision_lego OWNER mikey;
GRANT ALL PRIVILEGES ON DATABASE vision_lego TO mikey;
\q
```

- **Database name**: `vision_lego`
- **DB user**: `mikey`
- **Resulting DATABASE_URL**: `postgresql://mikey:your_strong_password@localhost:5432/vision_lego`
- This value goes in the local `.env` file and also as the `DATABASE_URL` GitHub Actions secret

### Dependency policy
- **Do not add any npm/pnpm dependency not already listed in this file or in `package.json`** without explicit confirmation
- Prefer native Web APIs and SvelteKit built-ins over third-party libraries wherever possible
- If a new dependency is truly necessary, flag it and explain why before installing it

### Users
- **Local dev machine**: `mikeydoya` (regular user with sudo, password required)
- **Droplet**: `mikey` (regular user with limited passwordless sudo for deployment commands only)
- Neither environment uses `root` directly — good security practice
- SSH key: `~/.ssh/Digital_Ocean_Key`

### Nginx and HTTPS
- **Current state**: HTTP only, no domain yet — the app is accessed via the droplet's IP address
- **Nginx config to generate**: HTTP only (port 80), reverse proxy to `localhost:3000`
- **Future**: when a domain is purchased and pointed to the droplet, add HTTPS via Certbot (Let's Encrypt) — do not implement this yet
- Do not generate any HTTPS/SSL configuration until explicitly asked

### How deployment works
Claude Code runs on `mikeydoya`'s local machine, not on the server. The build always happens locally. The droplet only receives the compiled output and runs it.

Deployment flow:
1. `pnpm build` runs locally on `mikeydoya`'s machine
2. Developer pushes to `main` on GitHub
3. GitHub Actions SSHes into the droplet as `mikey`
4. Actions transfers the compiled output (`build/`, `package.json`, `pnpm-lock.yaml`) to the droplet
5. Actions runs `pnpm install --prod` on the droplet (no build — production deps only)
6. Actions runs `pm2 restart vision_lego` (or `pm2 start ecosystem.config.cjs` on first deploy)
7. Nginx reverse-proxies HTTP traffic from port 80 to `localhost:3000`

### What Claude Code generates (automated)
- `.github/workflows/deploy.yml` — full GitHub Actions workflow (SSH as `mikey`)
- `ecosystem.config.cjs` — PM2 process config
- `nginx.conf` — HTTP-only Nginx reverse proxy (developer copies this to the server manually)

### What the developer does manually (one-time server setup)
The droplet has two users: `root` and `mikey`. Always use `mikey`.
`mikey` has passwordless sudo scoped only to Nginx and PM2 commands needed for deployment.

```sh
# 1. Install PM2 on the droplet
pnpm add -g pm2

# 2. After the first successful deploy, register PM2 with systemd so it survives reboots
pm2 startup        # copy and run the command it prints
pm2 save

# 3. Copy nginx.conf (generated by Claude Code) to the server
sudo cp nginx.conf /etc/nginx/sites-available/vision_lego
sudo ln -s /etc/nginx/sites-available/vision_lego /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

### What the developer does manually (one-time GitHub setup)
Add these secrets in the repo under Settings → Secrets → Actions:
- `DROPLET_HOST` — droplet IP address
- `DROPLET_USER` — `mikey`
- `DROPLET_SSH_KEY` — contents of `~/.ssh/Digital_Ocean_Key` (the private key)
- `DATABASE_URL`, `BETTER_AUTH_SECRET`, `BETTER_AUTH_URL` — injected into `.env` on the droplet during each deploy
